# 世界反转（黑白）

> 依据代码：`Logic/Level/LevelManager`、`Logic/Level/WorldPolarity`、`Logic/Level/IReverse`、
> `Logic/Actor/Player/PlayerLogic`、`Logic/Actor/Player/AttackGroup`、`Presentation/Root/GameRoot`、
> `Presentation/Combat/CombatRoot`、`Presentation/Level/GroundIniter`、
> `Presentation/UI/Panel/GameplayPanel`、`Logic/Event/Events`（`WorldReversed` / `WorldPolarityChanged`）。

## 一、谁持有世界

| 项 | 位置 | 说明 |
|---|---|---|
| 世界极性（唯一真相） | `GameRoot.World`（`WorldPolarity.White` / `Black`） | 常驻对象持有，**跨关保留**；只有退出播放（`OnDisable`）才回到白 |
| 世界极性的镜像 | `LevelManager.World` | 每关一个实例，进关时用 `new LevelManager(id, door, GameRoot.World)` 接住常驻值，之后靠 `WorldPolarityChanged` 同步 |
| `LevelManager` 归属 | `CombatRoot.Attach` 创建、`OnDestroy` 注销 | 不跨关，所以它只负责"本关谁要换色"，不负责记住极性 |
| 换色对象 | `IReverse` 实现（目前只有 `GroundIniter`） | `CombatRoot` 装配时扫当前场景全部 `MonoBehaviour`，把 `is IReverse` 的登记进 `LevelManager` |

`RegisterReverse` 在登记当场套一次当前极性，所以"先出生的地面"和"晚登记的物体"不会停在错色上；
上一关是黑世界时，新场景的地面装配完就已经是黑的。

`LevelManager.Init` 会广播一次 `WorldPolarityChanged(World)`：这就是"进关时把跨关保留的极性告诉全场"的那一拍。
玩家在 `CombatRoot` 之前装配（`SceneOrder.Player < World`），此时已经在监听，所以玩家的黑白形态也在同一帧对齐。

## 二、一次反转的路径

1. `PlayerLogic` 每固定帧看 `InputSnapshot.ReversePressed`：**极性满**才生效，其余情况直接忽略。
2. 生效时先 `PolarityGauge.Clear()`，再 `ActorLogic.ResetHealth()` 把血量回满并 `Announce()`，最后广播 `WorldReversed`
   （空结构体，只表示"有人请求反转"，不携带值）。
   回血放在广播前：`GameplayPanel` 收到事件会重绘血量图标，晚一步就画的是旧值。
3. `GameRoot.OnWorldReversed`：白↔黑互换**自己持有的常驻值**，然后广播 `WorldPolarityChanged(World)`。
   翻转只发生在这里，`WorldReversed` 到 `WorldPolarityChanged` 是一对一，不存在两处各算一套。
4. `LevelManager.OnWorldPolarityChanged`：把镜像值改成事件里的值，再逐个 `IReverse.Apply(World)`；单个物体的异常被隔离，
   不会让剩下的地面停在上一个世界。
5. `AttackGroup.OnWorldPolarityChanged`：`IsBlack = (World == Black)`，黑/白攻击链跟着换。
6. `GameplayPanel` / `DebugPanel`：同样是"按事件里的值取色"，不是各翻一次——所以进关补发的那一次也能把界面刷对。

订阅者一律**同步**而不是翻转：漏收一次事件（比如进关时才补发的第一次）会让翻转派的计数永久错位。

## 三、跨场景的目标门改由事件带走

`LevelManager` 现在随场景销毁，`GameRoot` 在 `Rebind` 时已经问不到 `PendingDoorId`。
改为：`LevelManager` 在 `SceneManager.LoadScene` **之前**广播 `LevelLoadRequested(nextDoor, enterTag, enterFace)`，
`GameRoot` 记下这三个值，切场景后 `Rebind` 里 `TakePendingDoor` 取走并清空。

- 必须在 `LoadScene` 之前发：单场景加载是同步的，`sceneLoaded → Rebind` 发生在 `LoadScene` 内部就返回了。
- 取一次就清空：残留的落点会在之后的死亡重载里把玩家丢到错的门口。

## 四、Q 键为什么不在 `InputSys.inputactions` 里

`Generated/InputSys.cs` 是 Input System 的生成物（AGENTS.md §3 禁止手改），而改了 `.inputactions`
要 Unity 重新导入才会重写生成类——中间那段时间 `Player.Reverse` 根本不存在，编译门必红。
所以 Q 暂时在 `InputProvider` 里用独立的 `InputAction("Reverse", InputActionType.Button, "<Keyboard>/q")` 建。

要收编进资产（推荐后续做）：在 `Player` map 加 `Reverse`（Button）绑 `<Keyboard>/q` → 让编辑器重新导入生成
`InputSys.cs` → 把 `InputProvider` 的 `_reverseAction` 换成 `_input.Player.Reverse`。

## 五、硬约束

- **一个关卡场景只能有一个 `CombatRoot`**：`LevelManager` 每个实例都订阅 `RequestNextDoor`，两个实例会把同一扇门响应两次。
- 场景里没有 `CombatRoot` 就没有门推进、也没有地面换色（反转到常驻极性仍然成立，只是没人把颜色推下去）。
- `IReverse` 由 `FindObjectsByType` 扫**全部已加载场景**，所以常驻对象（`DontDestroyOnLoad`）不要实现 `IReverse`。
- `GroundIniter` 换色只改 RGB，保留各自 alpha：地面若有半透明装饰，不会被刷成不透明。
- 反转不打断任何状态：下蹲、充能、残影、过门期间按 Q 都会照常生效。
