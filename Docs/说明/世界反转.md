# 世界反转（黑白）

> 依据代码：`Logic/Level/LevelManager`、`Logic/Level/WorldPolarity`、`Logic/Level/IReverse`、
> `Logic/Actor/Player/PlayerLogic`、`Logic/Actor/Player/AttackGroup`、`Logic/Actor/Enemy/EnemyLogic`、`Presentation/Root/GameRoot`、
> `Presentation/Level/LevelRoot`、`Presentation/Combat/CombatRoot`、`Presentation/Level/GroundIniter`、
> `Presentation/UI/Panel/GameplayPanel`、`Logic/Event/Events`（`WorldReversed` / `WorldPolarityChanged`）。

## 一、谁持有世界

| 项 | 位置 | 说明 |
|---|---|---|
| 世界极性（唯一真相） | `SceneContext.World`（`GameRoot` 私有持有，`GameRoot.World` 转发） | 常驻对象持有，**跨关保留**；只有退出播放（`GameRoot.OnDisable` → `SceneContext.Reset`）才回到白 |
| 世界极性的镜像 | `LevelManager.World` | 每关一个实例，由 `LevelRoot` 用 `new LevelManager(id, door, GameRoot.World, GameRoot)` 接住常驻值，之后靠 `WorldPolarityChanged` 同步 |
| 关卡起点 | `SceneFlowConfig` | 现在只管入口状态（`GameState`），不再覆盖极性：极性一律从上一关继承 |
| `LevelManager` 归属 | `LevelRoot`（只在关卡场景存在）：`Attach` 里建、`Init`、随场景销毁 `Dispose` | 不跨关，所以它只负责"本关谁要换色"，不负责记住极性；`GameRoot` 不再持有它 |
| 换色对象 | `IReverse` 实现：`GroundIniter`（整片地面反色）、`ColorGround`（只在指定极性存在，另一极性整块消失）、`WeakGround`（碎裂地面跟着换底色，透明度归它自己的闪烁） | 自己在 `Start` 里调 `Attach` 向 `LevelRoot.Current` 登记、`OnDestroy` 注销；`LevelManager` 还没建时由 `LevelRoot` 的待登记表暂存 |

`RegisterReverse` 在登记当场套一次当前极性，所以"先出生的地面"和"晚登记的物体"不会停在错色上；
上一关是黑世界时，新场景的地面装配完就已经是黑的。

**进关不重播 `WorldPolarityChanged`**：`LevelManager.Init` 只订阅不发布。敌人收到事件是 `_black = !_black`
（取反语义，初值是 Inspector 上的 `blackForm`），重播一次就会把黑世界里刚配好的敌人翻成白。
需要初值的对象各自在装配时主动读：玩家 `PlayerController.Attach` 里 `PlayerLogic.SetWorld(GameRoot.World)`，
`IReverse` 靠 `RegisterReverse` 当场套色。

## 二、一次反转的路径

1. `PlayerLogic` 每固定帧看 `InputSnapshot.ReversePressed`：**极性满**才生效，其余情况直接忽略。
2. 生效时先 `PolarityGauge.Clear()`，再 `ActorLogic.ResetHealth()` 把血量回满并 `Announce()`，最后广播 `WorldReversed`
   （空结构体，只表示"有人请求反转"，不携带值）。
   回血放在广播前：`GameplayPanel` 收到事件会重绘血量图标，晚一步就画的是旧值。
3. `GameRoot.OnWorldReversed`：白↔黑互换**自己持有的常驻值**，然后广播 `WorldPolarityChanged(World)`。
   翻转只发生在这里，`WorldReversed` 到 `WorldPolarityChanged` 是一对一，不存在两处各算一套。
4. `LevelManager.OnWorldPolarityChanged`：把镜像值改成事件里的值，再逐个 `IReverse.Apply(World)`；单个物体的异常被隔离，
   不会让剩下的地面停在上一个世界。
5. `PlayerLogic.OnWorldPolarityChanged`：`SetWorld(evt.World)`，黑/白攻击链跟着换。**玩家黑白只存这一份**：
   `PlayerController` 与 `AttackGroup` 都读 `PlayerLogic.IsBlack`（`AttackGroup` 拿的是构造时注入的 `Func<bool>`，
   自己不存副本、也不订阅事件）。
6. `GameplayPanel` / `DebugPanel`：按事件里的值取色，不是各翻一次。
7. `EnemyLogic`：`ChaseAllowed = (World != Black)`，黑世界不追人（开火不受影响，见 `敌人状态机.md` 第六节）。
   黑白的初值来自各控制器 Inspector 的 `blackForm`（`EnemyLogicBase(motor, config, ai, black)`），
   之后只由事件翻转，所以事件必须只在真的反转时发一次。

玩家与 UI 一律**按事件里的值同步**而不是翻转；只有敌人是取反派，这也是"事件不许重播"的原因。

## 三、跨场景的目标门由 SceneContext 带走

`LevelManager` 随关重建，`GameRoot` 在 `Rebind` 时已经问不到它的字段。
改为：`LevelRoot` 建 `LevelManager` 时把 `GameRoot` 作为 `ISceneTransfer` 注入；
切场景前 `LevelManager` 调 `RequestLevelLoad(nextDoor, enterTag, enterFace)`，
`GameRoot` 把三个值写进私有的 `SceneContext`，切场景后 `Rebind` 里 `TakeNextDoor` 取走先存着，
等新场景的 `LevelRoot` 报到（`BindLevelRoot`）再用本关的门索引解析落点。

- 必须在 `LoadScene` 之前写：单场景加载是同步的，`sceneLoaded → Rebind` 发生在 `LoadScene` 内部就返回了。
- 没有 `ISceneTransfer`（测试或裸建 `LevelManager`）时不加载，只报错：落点带不过去，加载了玩家也只会站在场景默认位置。
- 取一次就清空：残留的落点会在之后的死亡重载里把玩家丢到错的门口。

`SceneContext` 里还有存档点、待复活点与进门口，各自的写入方与不变式见 `跨场景数据.md`。

## 四、Q 键为什么不在 `InputSys.inputactions` 里

`Generated/InputSys.cs` 是 Input System 的生成物（AGENTS.md §3 禁止手改），而改了 `.inputactions`
要 Unity 重新导入才会重写生成类——中间那段时间 `Player.Reverse` 根本不存在，编译门必红。
所以 Q 暂时在 `InputProvider` 里用独立的 `InputAction("Reverse", InputActionType.Button, "<Keyboard>/q")` 建。

要收编进资产（推荐后续做）：在 `Player` map 加 `Reverse`（Button）绑 `<Keyboard>/q` → 让编辑器重新导入生成
`InputSys.cs` → 把 `InputProvider` 的 `_reverseAction` 换成 `_input.Player.Reverse`。

## 五、硬约束

- **一个关卡只能有一个 `LevelRoot`**：它每关新建一个 `LevelManager`，`RequestNextDoor` 只订阅一次；别处不许再 `new`。
- 场景里没有 `CombatRoot` 照样有门推进、同关传送与地面换色：这三件事全归 `LevelRoot`，`CombatRoot` 只管残影与子弹。
- **没有 `LevelRoot` 就不是关卡**（开始场景）：没有 `LevelManager`、不解析进门落点、`IReverse` 登记直接被忽略。
- `IReverse` 自注册，不扫场景：`Attach` 要幂等，`Attach` / `OnDestroy` 成对；常驻对象（`DontDestroyOnLoad`）不要实现它，换关时它会被当成上一关的换色对象清掉。
- `GroundIniter` 换色只改 RGB，保留各自 alpha：地面若有半透明装饰，不会被刷成不透明。
- 反转不打断任何状态：下蹲、充能、残影、过门期间按 Q 都会照常生效。
- 世界极性跨关保留：新关卡接着上一关的黑/白走，没有"每关强制回白"的开关。
- 玩家极性值同样跨关保留：`SceneContext` 记账，`PlayerController.Attach` 恢复后由 `GameRoot` 重播；
  但反转成功与复活都会 `Clear`，所以死亡重开是空条，活着过门才带得走。
- **玩家黑白只有 `PlayerLogic` 一份**（`IsBlack` / `SetWorld`）：`PlayerController` 与 `AttackGroup` 都读它，
  别再各自订阅 `WorldPolarityChanged`。进关时没有任何广播，靠 `PlayerController.Attach` 里的 `SetWorld(GameRoot.World)`；
  显示则在 `FixedTick` 里比 `IsBlack != _shownBlack` 才刷——`ApplyInvert` 会对粒子配色字段反复取反，每帧调用会翻回来。
