# 敌人状态机

> 依据代码：EnemyLogic（持有索敌结果 / 丢目标计时 / 接触伤害间隔 / 开火冷却）、EnemyMoveGroup（2 态切换）、EnemyPatrolState / EnemyChaseState。
> 登记、驱动、回收与全体刷新在 `Presentation/Combat/EnemyMgr`（第十节），敌人本身不是场景根。
> 探测与贴地看 EnemyMotor 与预制体上的 DetectCollider；数值全在 `Assets/Resources/Data/Enemy/EnemyConfig.asset`。
> 敌人有两套输出：贴身接触（AttackBox + `contactDamage` / `contactInterval`）与「看见玩家打一发子弹」（第六节）。
> 两者都不是状态机里的一态：没有攻击状态、没有前摇。

## 一、每物理帧顺序

1. 采样世界：EnemyMotor 以 `View/Bottom` 为脚底基准探地面（踩地时贴回并清零 vy）、探墙、探朝向那一侧的悬崖，组装 WorldInfo。
2. BeginStep：读真值、清增量、外部速度衰减一次。
3. 写入本帧索敌结果（DetectCollider 的进 / 出事件维护的可见性与玩家位置）与巡逻范围（`Start` 里快照下来的世界 x 边界）。
4. 更新丢目标计时：看得见清零并记下位置，看不见累加 Δt。
5. 判开火：只在「看不见 → 看得见」的那一帧出一发（第六节）。
6. EnemyMoveGroup：先判抢占，再判当前状态是否结束，最后才 Tick 状态本身。
7. 当前状态 Tick：提交横向速度指令。
8. ApplyGravity → Commit。

接触伤害不在这条链上，它由物理回调在物理步内触发（见第五节）。

## 二、切态判定

切态只有两条路，都在 EnemyMoveGroup 里：

| 机制 | 条件 | 下一态 |
| --- | --- | --- |
| 抢占 | 巡逻中 · 玩家在探测范围内 · 世界是白 | 追踪 |
| Fallback | 追踪结束（丢目标超时 / 世界转黑） | 巡逻 |
| Fallback | 首帧（无当前状态） | 巡逻 |

- 「丢目标超时」= 看不见玩家且超过 `loseTargetTime`，判定在 EnemyChaseState.IsDone，去处由 Fallback 决定。
- 「世界转黑」= `EnemyLogic.ChaseAllowed` 变 false。黑天**不追人**：已经追着的下一帧就被判结束回巡逻，正在巡逻的也不会被抢占进追踪。
- 抢占先于结束判定：同一帧里能抢就抢，抢不到才看 `IsDone`。
- 追踪没有主动结束点：只要还在警戒内就一路贴上去，玩家跑多远跟多远（崖边除外）。

## 三、巡逻

- 只在踩地时推进，离地一律刹车（坠落、被顶飞时不会在空中左右飘）。
- 范围：`EnemyController` 上的 `patrolOffset` + `patrolSize` 画出的方框，取它的**世界 x 边界**当左右折返点。
- 参数是**局部坐标**（相对敌人）：编辑器里框跟着敌人一起显示，改摆位框自动跟着；运行时在 `Start` 里换算成世界坐标**快照一次**，之后敌人自己怎么走、被顶飞到哪，框都不动。
- `patrolSize` 两个分量留 0（默认）= 不启用巡逻框，走到墙或悬崖才掉头；给组件点 Reset 会铺一个 18×3 的框当起点。
- 方向：到边界、贴墙、前方是悬崖，三者任一就掉头。
- 没有「以出生点为中心 ± 半径」这一说：框的位置由 `patrolOffset` 决定，默认 0 就是以敌人出生点为中心。

## 四、追踪

- 一直朝玩家的水平方向走，速度用 `moveSpeed`，没有冷却也没有停顿。
- 贴上就停：水平距离 ≤ `chaseStopDistance` 刹车，再近会一路把玩家顶走。它与攻击盒半径的关系见第五节。
- 玩家在悬崖对面就停在崖边（`LedgeAhead`），不会为了追人跳下去。
- 玩家刚离开探测范围时仍朝最后已知位置走；丢目标超时才回巡逻。

## 五、接触伤害（持续掉血）

- 载体是子物体 `AttackCollider` 上的 `AttackBox`（CircleCollider2D，Is Trigger）+ 敌人的 `IAttacker.ProduceDamage`。
- **进入即咬一口，之后按 `contactInterval` 反复咬**：`AttackBox.OnTriggerStay2D` 每物理帧问攻击者 `IIntervalAttacker.ReadyToHit(now)`，到点才结算。只写 `OnTriggerEnter2D` 的话玩家站着不动就只能吃到第一口。
- 间隔在 `EnemyLogic._contactCooldown`（Foundation.Cooldown），**只在命中成功后 MarkHit**：被玩家无敌窗挡掉的那次不消耗间隔，无敌一结束就接着掉血。
- 间隔必须 ≥ 玩家的 `invulnerableTime`（当前 0.4s），否则多出来的那几次会被无敌窗吞掉，看起来像「隔很久才掉一次」。
- 子弹等一次性攻击盒不受影响：它们不实现 `IIntervalAttacker`，Stay 分支直接跳过，只有进入那一下结算。
- **敌人刚体强制 `NeverSleep`**：Stay 依赖物理回调，玩家站着不动、双方刚体都睡着时物理对不再回调，掉血会断。
- 伤害方向按几何现算（从攻击盒指向受击盒中心）：用攻击者朝向会把人往怀里推。
- 攻击盒半径 0.9 + 玩家半宽 0.45 ≈ 1.35 ≥ `chaseStopDistance`，所以贴住时判定一定成立；把 `chaseStopDistance` 调到 1.35 以上就成了「看得见摸不着」。
- 站桩（`OpenAI = false`）时这条链路照常，敌人仍然咬人，只是自己不动。

## 六、开火（看见玩家打一发）

- 触发是**上升沿**：`EnemyLogic` 记着上一帧的可见性，只在「看不见 → 看得见」那一帧开一枪；一直看得见不会每帧打，出视野再进来才可能补下一枪。
- `fireInterval`（秒）是冷却，只用来拦住「反复进出视野」的连发：冷却没走完就再进来，那一枪直接吞掉，不排队。
- 弹道**只取横向**：取「玩家 x − 敌人 x」的符号（完全重合时退回朝向 `FaceSign`），没有仰角。出膛点 = 敌人中心 + `(sign × |bulletMuzzle.x|, bulletMuzzle.y)`。**`bulletMuzzle` 在控制器的 Inspector 上，不在 config 里**：x 一律填正数，左右由代码翻；选中控制器时编辑器会画出这个点（`EnemyGizmos.DrawMuzzle`，按当前朝向镜像），有子弹预制体才画。
- 出膛点建议大于「身体半径 + 子弹半宽」：落在身体里的话那一帧子弹的触发盒就压着自己的受击盒。真正兜底的是 `Bullet.Initialize` 里的 `SetOwnerRoot`（见下条），这条只剩观感意义。
- **子弹容器不挂在敌人层级里**（`BulletField` 是全局独立根对象）：`EnemyLogic.OnFixedTick` 的顺序是「`TryFire` → `_moveGroup.Tick`」，转身发生在 `Tick` 里（`Face` setter 翻根节点 `localScale.x`）。子弹若挂在敌人下面，转身那一帧生成的子弹会当场继承负缩放，`localPosition` 被镜像到身体另一侧——表现就是「转身那一刻发出的子弹不在枪口」。容器独立之后子弹的根是自己的，`AttackBox` 的「同根」自伤保险随之失效——改由 `Bullet.Initialize` 里的 `AttackBox.SetOwnerRoot(开火者)` 挡住：属于开火者层级的受击盒一律跳过。
- `bulletSpeed ≤ 0` 等于关掉开火；`EnemyController.bulletPrefab` 留空也等于关掉（只巡逻 / 追踪，不刷警告）。
- 站桩（`OpenAI = false`）不开火：`OnFixedTick` 在推进状态机之前就 return 了。
- **黑形态只关追击，不关开火**：两条是分开的需求，黑形态的敌人照样会打进来的人；要一起关就再加一条闸门。
- 子弹伤害随子弹下发（`bulletDamage` / `bulletKnockback`），但落到玩家身上时整个被 `PlayerConfig.destruction`（破坏力）顶掉：敌人只知道自己开了火。命中由 `Bullet.OnTriggerEnter2D` 撞到受击盒后自己结算，**不看 `TakeDamage` 的返回值**：玩家在无敌窗里也照样收弹，不会贴着人等到窗口结束再扣一次。

## 七、丢目标计时的单一来源

- 丢目标计时只在 EnemyLogic 里维护，状态与状态组都只读，不要各自再存一份。
- 巡逻范围是表现层每帧喂进来的 `EnemyArea`（无界 = 整平台；地面敌人用 `EnemyArea.SpanX` 只给左右边界），状态只读，不要自己记边界。

## 八、站桩（EnemyController.OpenAI = false）

- `EnemyMoveGroup` 整个不推进：不进任何状态、不巡逻不追，出生就待在原地。
- 每帧仍要 `BrakeTowardsX`：刚体没有线性阻尼，被玩家撞一下会一直滑，站桩必须自己刹住。
- 不开火：开火判定在状态机推进之后，站桩分支早就 return 了。
- 受击照常：`TakeDamage` 仍然进 `ConditionGroup`，受伤态、无敌窗、击退都按常规走。
- 伤害值恒为 0：进 `TryApply` 前把 `Damage.Amount` 抹成 0，于是不扣血、不进无敌窗（0 伤害本就是「纯效果」语义），血永远满着，也就永远走不到销毁。
- 只是「打不死」，不是「打不中」：命中判定、受击表现、击退位移都还在，方便当靶子练连段。

## 九、预制体接线（Enemy.prefab）

- 根节点：Rigidbody2D + EnemyMotor + EnemyController；config 只挂在 EnemyController 上，装配时注入给 EnemyMotor。
- 子物体按名字找，不在 Inspector 里连线：View（显示）、BodyCollider（身体，非触发器）、DetectCollider（索敌范围）、AttackCollider（接触伤害）。
- **三根碰撞体的名字、层与触发器由 `EnemyColliderConfig` 资产定，`EnemyColliderSetup.Apply` 在 Awake 里按它统一写**，预制体上勾成什么样都会被覆盖：`BodyCollider` 保持实体（不设触发器）但排除 `Player(7)` 与 `Enemy(8)`——敌人不与玩家、同类互相推挤；`AttackCollider` 上每一颗碰撞体都设成触发器并排除 `Enemy(8)` 层（不误伤同类）；`DetectCollider` 同样全部设成触发器，`Include` 只留 `Player(7)`、`Exclude` 抹掉除 Player 外的所有层（同类、地面、场景物都不再进视线）。层号也在这个资产里改，预制体不用动；名字对不上就只报警告、那根盒不会被配置。
- 配色只有一件事：各敌人 `View` 摆自己的初始色，敌人是黑形态时 `rgb = 1 - rgb` 取反、alpha 不动，回白形态还原。逻辑在 `Presentation/Actor/Enemy/EnemyTint.cs`（Awake 缓存设计态颜色，缓存不写回），控制器只在 `Black` 变化时调一次 `Apply`。**任何状态都不再改色**，唯一还能改色的只有受击闪白（材质 `_FlashAmount`，与这里无关）。
- **黑白是敌人自己的，不看世界**：五个控制器都有 `blackForm`（勾上 = 黑形态），构造时注入 `EnemyLogicBase`，`Black` 之后每收到一次 `WorldPolarityChanged` 就翻面。所以「世界黑、敌人白」成立，攻击选白分支、上色用白色一套。**这条依赖「事件只在极性真的变了时发」**：同极性重复上报会把敌人翻错。
- 身体盒排不排同类单独有个开关（`bodyExcludeEnemy`，默认勾着）：**只管 `BodyCollider`**，关掉后同类之间会互相挡住、挤不开；攻击盒照旧排 Enemy（不误伤同类）、探测盒照旧只认 Player，两者都不受这个开关影响。
- 碰撞体资产要在 `Assets/Resources/Data/Enemy/` 下建（右键 Create ▸ Refraction ▸ Settings ▸ EnemyCollider），文件名必须正好是 `EnemyColliderConfig`：代码按 Resources 路径加载，缺了就用脚本里的默认值并打一条 warning。
- 巡逻范围不再是子物体：`EnemyController` 的 `patrolOffset` / `patrolSize` 给的是局部坐标，`OnDrawGizmosSelected` 里画淡绿线框——没运行时画跟随敌人的参数框，跑起来画 `Start` 里那份世界坐标快照（框钉在世界上，敌人怎么走都不动）。各敌人的框与视线范围都由 `EnemyGizmos` 画，控制器只挑颜色与画哪一种。旧预制体上的 `PatrolCollider` 子物体现在完全不用了，留着也不影响。
- `View` 下必须有 `Bottom` 与 `Top` 两个空物体：脚底探测、贴地、悬崖探针都以 Bottom 为基准；缺了就退回碰撞体底边（贴地会有偏差）。
- `BodyCollider` 上挂 HurtBox、`AttackCollider` 上挂 AttackBox，两者由 `HitBoxBinder.Bind` 在 Attach 里接上自己（一个挨打、一个出伤害）。
- 这两类盒按 `GetComponentsInChildren` **全接**，可以挂多个：根上一个 + 子物体上若干个都会接到同一份逻辑（`GetComponentInChildren` 只回第一个，根上有盒时子物体上的会全被挡住）。攻击盒同时记下归属根，自身层级的排除才准。
- EnemyDetectZone 由 EnemyController 在 Awake 里补挂到 DetectCollider 上，不用手工添加。
- **子弹预制体在 EnemyController 的 `bulletPrefab` 上接线**（唯一需要 Inspector 连的引用）：留空 = 这只敌人不开火。预制体带上 Rigidbody2D + 触发碰撞体 + 可选 AttackBox 即可，`Bullet` 由 BulletPool 补挂。
- 出膛点是同一个组件上的 `bulletMuzzle`（局部坐标，x 随朝向镜像），不进 config：改枪口不用动那三份 `*Config.asset`，选中控制器就能在场景里看到点。
- **子弹的池、实例与活跃表都不再跟着敌人走**：敌人只在自己的预制体上配 Prefab，第一次 Tick 时向 `CombatRoot` 领一个发射口（`CombatRoot.Acquire`，登记成 `BulletFaction.Enemy`）。
  `CombatRoot` 按 **Prefab** 建池（`BulletPool`）并驱动全局 `BulletField`；相同外观的子弹共用一池，不同外观绝不串池。
  回收 / 刷新只清**这只敌人自己**发的子弹（`BulletLauncher.Clear`），不销毁任何容器，也不碰别人的弹。
- 刚体参数由 EnemyMotor 在 Awake 里强制：Dynamic、gravityScale = 0、冻结旋转、插值、不休眠。重力只有逻辑账本那一套。

## 十、管理、死亡与刷新

- **敌人不是场景根**：五个控制器都不再实现 `ISceneRoot` / `IPhysicsTicked`，`GameRoot.SceneRoots` 里看不到单只敌人。`Order` 也不再由敌人各自声明，驱动顺序由 `EnemyMgr` 的注册顺序决定。
- 分工：控制器只做**装配、采样、执行、复位**；**列表、驱动、回收、刷新**是 `EnemyMgr` 的事；`CombatRoot` 只负责调用 `EnemyMgr`；`GameRoot` 不认识任何一只具体的敌人（它只有一个 `Combat` 入口）。
- 运行时契约 `IManagedEnemy`（`Presentation/Actor`）只有这几件：`SpawnState` / `IsDead` / `ManagedTick(dt)` / `Recycle()` / `ResetToSpawn()`。**`MonoBehaviour` 生命周期、`Transform`、`Attach()` 这些不进 Logic 层**——Logic 仍然不知道敌人有没有身体。
- 这份契约由 `Presentation/Actor/ManagedEnemyController`（**薄管理壳**）统一实现，五个控制器都继承它，不再各写一遍。壳只持有 `_spawn` / `_attached` / `_dead` 与 `Root`，`Start` 里走「`Assemble()` → 采快照 → `EnemyMgr.Join`」，`OnDestroy` 里走「`OnDispose()` → `Leave`」，并统一了四条守卫：未装配 / 已死不 `Tick`、`Recycle` 的 `SetActive(false)`、`ResetToSpawn` 的首尾 `SetActive` 外壳、`BodyAlive` 变 false 就标死。
- 派生只实现六个必选钩子：`BodyAlive` / `CaptureSpawn` / `Assemble` / `OnTick` / `OnRecycle` / `ResetBody`，外加可选的 `OnDispose`。**壳里没有血量、子弹、视线、状态机**——正因为不认识这些，才要把它们做成钩子；想往壳里塞玩法之前先想清楚，它一旦知道敌人有什么，五种敌人就开始互相牵制了。
- `EnemySpawnState` 是纯值快照，`Start` 里采一次：`Kind / Position / FaceSign / InitialBlack / InitialHealth`。**不存每帧 AI 状态、冷却、当前速度**：刷新语义是「回到出生那一刻」，不是「存档续玩」。要续玩得另建一条数据链，别往这个结构里加字段。
- `EnemyKind`（`None / Ground / E_First / E_Second / Spliter / Warrior`）只给调试与以后按类批量操作留口子，`EnemyMgr` 本身不按种类分支。
- **登记顺序靠 Pending 兜**：敌人 `Start` 早于 `CombatRoot.Attach`，那时 `EnemyMgr` 还没建。`EnemyMgr.Join` 在 `_active == null` 时先排进静态 `Pending`，`EnemyMgr` 构造时 `AdoptPending()` 收编。所以不用改 `SceneOrder`，也不用让敌人在 `Start` 里等谁。
- **死不是销毁**：`ManagedTick` 末尾发现 `!IsAlive` 就标 `_dead`，`EnemyMgr.FixedTick` 当场把它迁进回收表并 `Recycle()`（清自己的敌弹 + `SetActive(false)`）。身体留着，刷新时原样复活——省掉重新实例化，也让「刷新后每只敌人都回到出生点」变成唯一一条路径。
- 回收后不再被驱动：`_dead` 的不在 `_alive` 里，`ManagedTick` / `RenderTick` 都碰不到它；`SetActive(false)` 顺带停掉物理与触发器回调。
- `ResetAll()`：先按注册顺序复位存活，再把回收表里的复位并加回 `_alive`，最后 `_resetCount++`。**存活与已死走同一个 `ResetToSpawn`**，所以「没死但被打残、被引远了」的敌人也会回满血、回出生点。
- `ResetToSpawn` 的顺序有讲究，别调换：
  1. **开头先 `SetActive(false)`**：不先关掉的话，下面 `SpawnAt` 把身体搬走会让探测器对旧位置补发一组 Exit；
  2. 重建 Logic 并 `SetHealth(SpawnState.InitialHealth)`；黑白用 `InitialBlack` 而**不是当前 `Black`**，否则刷新后形态被上一次世界极性带跑；
  3. `HitBoxBinder.Bind` 把新 Logic 重新接到那几颗盒上（旧 Logic 已被 `Dispose`）；
  4. 清空敌弹并 `BindLauncher`；
  5. `EnemySight.Reset()` 清可见性与缓存的玩家引用；
  6. `FaceTowards` + `SpawnAt(SpawnState.Position, zero)` 归位、清零速度；
  7. 重上色；
  8. **末尾 `SetActive(true)`**：让探测器对当前重叠重发一次 Enter，第 5 步清掉的视线才补得回来。漏了这一步，刷新后站在玩家面前的敌人会看不见人。
- 第 1、8 两步在壳的 `ResetToSpawn` 里，2–7 在各派生的 `ResetBody` 里；**派生不要再自己碰 `SetActive`**，壳已经包好了。
- 蓄力表现、受击闪光随 Logic 重建自然归零（`HurtFlash` 每帧记账，新 Logic 没有 `ChargingShot`、血量是满的）；`E_Second` / `Spliter` 额外要复位 `View` 角度与 `_dashAimed` / `_aimLocked`，这些不在 Logic 里。
- **刷新时机**：`CombatRoot` 订阅两个事实事件，回调里只置 `_refreshPending = true`，真正的 `ResetAll()` 在**下一个物理帧开头**跑。这样天然满足「玩家先落点、回血、进无敌窗，敌人再复位」——复活当帧玩家还站在旧位置也无所谓。
  - `CheckpointActivated`：存档点存档成功时发（`PlayerController.TrySaveCheckpoint` 末尾）。
  - `PlayerRespawned`：同关复活时发，两条路各发一次——有存档点走 `SpawnTo(checkpoint)`，没存档点走 `RespawnToLastGrounded()`。**跨关转场不发**：新场景的敌人是新身体，`EnemyMgr` 也换了一份新的。
- 换场景时 `EnemyMgr.Dispose()` 只清自己那两份表；`if (_active != this) return;` 之后才置空并清 `Pending`——旧场景的销毁可能排在新场景入队之后，无条件清会把新场景的敌人丢掉。
- 调试：`DebugPanel` 的敌人块首行读 `root.Combat.Enemies`，显示 `敌人 活N 尸N 刷N`。
