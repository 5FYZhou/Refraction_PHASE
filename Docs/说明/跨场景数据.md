# 跨场景数据（SceneContext）

> 依据代码：`Logic/Level/SceneContext`、`Logic/Level/ISceneTransfer`、`Logic/Level/CheckpointBook`、
> `Presentation/Root/GameRoot`、`Presentation/Level/LevelRoot`、`Presentation/Root/SceneFlowConfig`。

## 一、为什么集中

这些数据原先散在 `GameRoot` 上：`_pendingDoorId/_pendingDoorTag/_pendingDoorFace`、`_entry/_entryTag/_entryFace/_hasEntryPoint`、
`_checkpoints/_pendingRespawn/_hasPendingRespawn`、`_world`。它们语义一致（**切场景后还得记住**），分散的代价是：
清空逻辑要写好几遍、漏一处就变成"淡出到错的门口"；新加一项要改 `GameRoot` 好几处；清单本身也看不出哪些是"取一次就清空"。

现在只有一个 `SceneContext`，由 `GameRoot` 私有持有（`_scenectx`），**写入一律走 `GameRoot` 的公开函数**。

## 二、装了什么

| 数据 | `SceneContext` 成员 | 谁写 | 谁读 |
|---|---|---|---|
| 世界极性 | `World` / `ReverseWorld` | `GameRoot.OnRequestWorldReverse` | `GameRoot.World`、`LevelManager`、敌人 / 玩家逻辑 |
| 下一扇门 | `SetNextDoor` / `TakeNextDoor` | `LevelManager`（经 `ISceneTransfer`） | `GameRoot.Rebind`（取走后存到字段，等 `BindLevelRoot` 再解析） |
| 进门口（已解析） | `SetEntry` / `ClearEntry` / `TryConsumeEntry` | `GameRoot.ResolveEntryPoint`（由 `BindLevelRoot` 调） | `PlayerController.Attach` |
| 存档点 | `SaveCheckpoint` / `TryGetCheckpoint` | `PlayerController`（经 `GameRoot.SaveCheckpoint`） | 死亡分支、`TryGetLocalCheckpoint` |
| 待复活点 | `BeginRespawn` / `CancelRespawn` / `TryConsumeRespawn` | `GameRoot.TryStartRespawnInCheckpointLevel` | `PlayerController.Attach` |
| 玩家血量 | `SetHealth` / `TryGetHealth` | `GameRoot.OnPlayerHealthChanged`（听 `PlayerHealthChanged`） | `PlayerController.Attach` |
| 玩家极性值 | `SetPolarity` / `TryGetPolarity` | `GameRoot.OnPlayerPolarityChanged`（听 `PlayerPolarityChanged`） | `PlayerController.Attach` |

## 三、写入口

`GameRoot` 对外只暴露函数，不暴露 `SceneContext` 实例——实例一旦泄露，下面第四节的不变式就没人守得住。

| 函数 | 调用方 | 说明 |
|---|---|---|
| `RequestLevelLoad(doorId, enterTag, enterFace)` | `LevelManager` | 实现 `ISceneTransfer`；逻辑层不认识 `GameRoot` 类型，只认这个窄接口 |
| `BindLevelRoot(levelRoot)` / `UnbindLevelRoot(levelRoot)` | `LevelRoot` | 关卡根装配完才报到；绑定时用本关门索引解析淡入前取走的落点，并标记关卡已就绪 |
| `SaveCheckpoint(pivot)` | `PlayerController` | 关卡 id 非法时只报一次错并返回 false |
| `TryStartRespawnInCheckpointLevel()` | `PlayerController` 死亡分支 | 成功才 `BeginRespawn`；`LoadScene` 抛异常时 `CancelRespawn` 回滚 |
| `TryConsumeEntryPoint` / `TryGetLocalCheckpoint` / `TryConsumeRespawnPoint` / `TryGetPlayerHealth` / `TryGetPlayerPolarity` | `PlayerController` | 读取，前三个也负责清空；血量与极性首关返回 false |

## 四、不变式（踩了不会编译失败，只会把玩家丢到错位置）

1. **取一次就清空**：`TakeNextDoor`、`TryConsumeEntry`、`TryConsumeRespawn`。残留值会让之后的重载（死亡、回档）落到上一次门的门口。
2. **门落点必须在 `LoadScene` 之前写**：发起方 `LevelManager` 随旧场景一起销毁，加载完再问就晚了。
3. **`Rebind` 只清不解析，解析在 `BindLevelRoot`**：切场景时新场景的门索引还不在（`LevelRoot` 要等场景根注册后才 `Attach`），提前解析只会拿到空表；
   本关不是经门进入的（首关、回档）时，`ClearEntry` 也不能留着上一关的落点。
4. **`Reset` 不清存档点**：退出播放只清本轮数据（极性、门、落点、待复活），存档点是玩家进度，重进仍要能从上次存档继续。
5. **世界极性、血量与玩家极性都不随关卡重置**：它们挂在 `SceneContext` 上跨关保留，只有退出播放走 `Reset` 才清。
6. **血量与极性必须在 `Announce` 之前恢复**：`PlayerController.Attach` 里先 `SetHealth` / `SetPolarity`，`GameRoot` 装配完紧跟着播报，
   顺序反过来界面会先闪一次满血 / 空条再跳回去。
7. **死亡回档前先 `Revive`**：跨关回档的新玩家从上下文读血，不先把满血落进上下文，新关就会带着 0 血重开、
   当场再死一次（同关回档只是不明显：`Revive` 也在 `SpawnTo` 之前）。`Revive` 同时 `Clear` 极性并播报，
   所以死亡重开是空条起步，跨关保留的极性只在**活着过门**时才带得走。
8. **`LevelManager` 归关卡根**：`LevelRoot` 在 `Attach`（`SceneOrder.Entry + 1`，晚于 `SceneFlowConfig` 写极性）里新建并 `Init`
   （`LevelManager(LevelId, this, GameRoot.World, GameRoot)`——`LevelRoot` 自己就是 `IDoorReader`），再把待登记表里的 `IReverse` 灌进去。
   `GameRoot` 只负责在 `BindLevelRoot` 里接住它并解析落点，**不找、不建、不持有**；门推进、同关传送、地面配色都不依赖 `CombatRoot`。
9. **进关不重播 `WorldPolarityChanged`**：`LevelManager.Init` 只订阅不发布。敌人的 `_black` 是取反语义
   （收到事件就 `!`），重播一次会把黑世界里刚配好的敌人翻成白。需要初值的对象各自在装配时主动读：
   玩家在 `PlayerController.Attach` 里 `PlayerLogic.SetWorld(GameRoot.World)`，`IReverse` 靠 `RegisterReverse` 当场套色。
10. **`IReverse` 向关卡根登记**：场景物在 `Start` 里调自己的 `Attach`，里面走 `LevelRoot.Current?.RegisterReverse(this)`；
   这一拍早于 `LevelRoot.Attach`，所以 `LevelRoot` 先用待登记表盛着，`LevelManager` 建成后统一灌进去并套一次当前极性。
   `OnDestroy` 成对注销；没有 `LevelRoot` 的场景（开始场景）直接忽略，不报错。
11. **门也是自注册**：`Door.Awake` 里 `LevelRoot.RegisterDoor(this)`、`OnDestroy` 注销，关卡根不再扫场景。
   门 `Awake` 可能早于 `LevelRoot.Awake`，那会儿进静态表，关卡根 `Awake` 时统一收进来；因此**初始未激活的门不会进索引**，
   要让它能当落点就必须先激活。`SelfId <= 0` 与同关 id 重复各报一条 error，后者只留先注册的那扇。
