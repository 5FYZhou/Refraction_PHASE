# 跨场景数据（SceneContext）

> 依据代码：`Logic/Level/SceneContext`、`Logic/Level/ISceneTransfer`、`Logic/Level/CheckpointBook`、
> `Presentation/Root/GameRoot`、`Presentation/Level/SceneFlowConfig`。

## 一、为什么集中

这些数据原先散在 `GameRoot` 上：`_pendingDoorId/_pendingDoorTag/_pendingDoorFace`、`_entry/_entryTag/_entryFace/_hasEntryPoint`、
`_checkpoints/_pendingRespawn/_hasPendingRespawn`、`_world`。它们语义一致（**切场景后还得记住**），分散的代价是：
清空逻辑要写好几遍、漏一处就变成"淡出到错的门口"；新加一项要改 `GameRoot` 好几处；清单本身也看不出哪些是"取一次就清空"。

现在只有一个 `SceneContext`，由 `GameRoot` 私有持有（`_scenectx`），**写入一律走 `GameRoot` 的公开函数**。

## 二、装了什么

| 数据 | `SceneContext` 成员 | 谁写 | 谁读 |
|---|---|---|---|
| 世界极性 | `World` / `SetWorld` / `ReverseWorld` | `GameRoot.ApplyWorldPolarity`（由 `SceneFlowConfig` 调）、`GameRoot.OnWorldReversed` | `GameRoot.World`、`CombatRoot` 装配、`LevelManager` |
| 下一扇门 | `SetNextDoor` / `TakeNextDoor` | `LevelManager`（经 `ISceneTransfer`） | `GameRoot.Rebind` |
| 进门口（已解析） | `SetEntry` / `ClearEntry` / `TryConsumeEntry` | `GameRoot.ResolveEntryPoint` | `PlayerController.Attach` |
| 存档点 | `SaveCheckpoint` / `TryGetCheckpoint` | `PlayerController`（经 `GameRoot.SaveCheckpoint`） | 死亡分支、`TryGetLocalCheckpoint` |
| 待复活点 | `BeginRespawn` / `CancelRespawn` / `TryConsumeRespawn` | `GameRoot.TryStartRespawnInCheckpointLevel` | `PlayerController.Attach` |

## 三、写入口

`GameRoot` 对外只暴露函数，不暴露 `SceneContext` 实例——实例一旦泄露，下面第四节的不变式就没人守得住。

| 函数 | 调用方 | 说明 |
|---|---|---|
| `ApplyWorldPolarity(world)` | `SceneFlowConfig.Attach` | 关卡配置覆盖极性，并广播 `WorldPolarityChanged`；晚于 `CombatRoot` 装配就只换了颜色、逻辑链仍是旧值 |
| `RequestLevelLoad(doorId, enterTag, enterFace)` | `LevelManager` | 实现 `ISceneTransfer`；逻辑层不认识 `GameRoot` 类型，只认这个窄接口 |
| `SaveCheckpoint(pivot)` | `PlayerController` | 关卡 id 非法时只报一次错并返回 false |
| `TryStartRespawnInCheckpointLevel()` | `PlayerController` 死亡分支 | 成功才 `BeginRespawn`；`LoadScene` 抛异常时 `CancelRespawn` 回滚 |
| `TryConsumeEntryPoint` / `TryGetLocalCheckpoint` / `TryConsumeRespawnPoint` | `PlayerController` | 读取，前两个也负责清空 |

## 四、不变式（踩了不会编译失败，只会把玩家丢到错位置）

1. **取一次就清空**：`TakeNextDoor`、`TryConsumeEntry`、`TryConsumeRespawn`。残留值会让之后的重载（死亡、回档）落到上一次门的门口。
2. **门落点必须在 `LoadScene` 之前写**：发起方 `LevelManager` 随旧场景一起销毁，加载完再问就晚了。
3. **`Rebind` 先 `ClearEntry` 再解析**：本关不是经门进入的（首关、回档）时，不能留着上一关的落点。
4. **`Reset` 不清存档点**：退出播放只清本轮数据（极性、门、落点、待复活），存档点是玩家进度，重进仍要能从上次存档继续。
5. **世界极性不随关卡重置**：每关新建的 `LevelManager` 用 `GameRoot.World` 起步，跨关保留黑/白；
   场景挂了 `SceneFlowConfig` 就以它的序列化值覆盖，没挂才沿用上一关。
6. **关卡配置最先装配**：`SceneFlowConfig.Order = SceneOrder.Entry`（`int.MinValue`），必须在 `CombatRoot`
   建立 `LevelManager` 之前写进上下文，否则地面会先按上一关的颜色刷一次。关内反转不受它影响，配置只在 `Attach` 写一次。
