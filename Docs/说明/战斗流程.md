# 战斗与受击流程

> 依据代码：`Logic/Combat`（契约）、`Logic/Actor/ActorLogic`（血量）、
> `Logic/Actor/ConditionGroup`（受击无敌与击退）、
> `Presentation/Actor/AttackBox`、`HurtBox`、`Presentation/Combat/Bullet/Bullet`。

## 一、契约

| 类型 | 位置 | 语义 |
|---|---|---|
| `IAttacker` | Logic.Combat | `ProduceDamage()` 给出一份伤害快照，不带目标 |
| `IHurtable` | Logic.Combat | `bool TakeDamage(in Damage)`，实现方是 `ActorLogic`（玩家与敌人共用）；返回值 = 血量是否真的减少 |
| `IHitLanded` | Logic.Combat | `OnHitLanded()`，伤害落地后的回报；只有真心扣血的攻击者才实现 |
| `IAlivable` | Logic.Combat | `IsAlive`，血量为 0 后为 false |
| `Damage` | Logic.Combat | `Direction`（指向受害者）/ `Amount`（点）/ `KnockbackSpeed`（单位/秒）/ `Source` |

## 二、一次伤害的路径

1. 表现层发现重叠：`AttackBox.OnTriggerEnter2D`（伤害结算）与 `Bullet.OnTriggerEnter2D`（残影与 Bound 分流）。
   持续型攻击者（`IIntervalAttacker`）另有 `OnTriggerStay2D` 那条路：贴着不走就按自己的间隔反复结算。
2. 定位受击实现：`HurtBox.Resolve(other)` —— 先找碰撞体上的 `HurtBox`，再往父级找，最后退回根上的 `IAttackable`。
   **碰撞体常常只是身体件**，`HurtBox` 却挂在另一个子节点上，只查本层会整台角色判不到。
3. `IAttackable.TakeDamage` → `ActorLogic.TakeDamage`（血量在这一层扣）→ `ConditionGroup.RegisterHit`：
   - 无敌窗内整下吞掉（返回 false，血量与击退都不变）。
   - 有伤害值就扣点；扣了血才开无敌窗（0 伤害的纯效果不占用窗口）。
   - 有击退就排队，等下一个固定帧起步。
4. 下一个固定帧 `ConditionGroup.Tick` 把击退交给 `HurtState`，并切到 `Hurt`。

## 三、固定帧序（`ActorLogic.FixedTick`）

```text
BeginStep → ConditionGroup.Tick → 子类逻辑 → ApplyGravity → Commit → ApplyGates
```

- `ConditionGroup.Tick` 先跑：它决定本帧是否受伤，并**创建** `MoveGates`。
- `ApplyGates` 必须压在 `Commit` 之后：门禁写的是绝对速度，早一步就会被本帧状态与重力盖回去。
- 因此受伤期间，任何状态写出的速度都被丢弃 —— 这是"击退期间不可控"的唯一实现点，不要在各状态里各自判断 IsHurt。

## 四、击退

- 初速度由 `Damage.KnockbackSpeed`（单位/秒）直接给出，受击者不再折算格数。
- 减速：`HurtState` 每帧减去 `KnockbackDecay × Δt`，减到 0 就退出受伤态；
  滑行位移 = `v0² / (2 × KnockbackDecay)`，想调远近就改伤害里的初速度或目标自己的阻尼。
- 纯横向击退不接管竖直速度（沿用帧首的 vy），否则空中挨打会当场停在半空。

## 五、各角色的伤害来源

| 来源 | 触发 | 数值 |
|---|---|---|
| 玩家的白子弹 | `Bullet` 上的 `AttackBox` 命中受击盒 | `bulletDamage` / `bulletKnockback`（`PlayerConfig`） |
| 玩家的普攻 / 突进 | `BlackDash` 下三只判定盒的 `AttackBox` 命中受击盒 | 普攻 `flatAttack*`、突进 `blackDash*`（`PlayerConfig`） |
| 敌人的接触伤害 | `AttackBox` 停在玩家受击盒里就按 `contactInterval` 反复结算 | `contactDamage` / `contactInterval` / `contactKnockback`（`EnemyConfig` 与 `E_SecondConfig` 各一份） |
| 敌人的子弹 | `EnemyLogic` 看见玩家的那一帧 `Launch` 一发；命中玩家同样是 `Bullet` 上的 `AttackBox` | 伤害取 `destruction`（`PlayerConfig` 的「破坏力」）；击退取敌弹自带的 `bulletKnockback` |
| 玩家的弹反 | 敌弹进入 / 停在 `Player/BlackRebound` 的三个范围里 | 速度沿用原弹；伤害 / 击退取 `bulletDamage` / `bulletKnockback`（`PlayerConfig`） |

- 伤害源按阵营分两支：`DamageSource.PlayerBullet` / `EnemyBullet`，由 `BulletLogic.PlayerOwned` 在开火时定死。
  玩家子弹（含弹反反出来的那一发）只伤敌人，敌人子弹只伤玩家。
- 敌人的 `AttackCollider` 与 `DetectCollider` 由 `EnemyColliderSetup.Apply` 在 Awake 里按 `EnemyColliderConfig` 资产统一改写：两根都强制成触发器，攻击盒排除 `Enemy(8)` 层、探测盒只认 `Player(7)` 层。预制体上勾了什么都会被覆盖，所以换形状、加第二颗碰撞体也不用回头补勾选；层号也在那份资产里改。身体盒排不排同类由 `bodyExcludeEnemy` 单独控制，与这两根无关。
  这条先在物理层落一次：`Bullet.Bind` 按伤害源改写碰撞体的 `ExcludeLayers`（见下），
  被击方再在 `TakeDamage` 里按源兜一层——同籍子弹互相穿过、既不扣血也不消失。
- 敌人子弹的数值不来自敌人：`EnemyConfig.bulletDamage` 只写进子弹自己的 `Damage`，落到玩家身上时被
  `PlayerConfig.destruction`（破坏力）整个顶掉——敌人只知道开了火，玩家掉多少血由玩家自己配。

- 敌人子弹与玩家子弹共用 `BulletLogic` + `Bullet`，但**各有各的实例与池**：玩家那套在 `CombatRoot`（池 32），
  敌人这套在 `EnemyController.Attach` 里随敌人创建（池 4）。两套的 `BulletField` 容器都是**独立根对象**：
  挂在角色下面时，`MoveMotor.Face` 转身翻根节点 `localScale.x` 会把子弹位置镜像到另一侧（表现为「转身那一帧的子弹不在枪口」）。
  敌人销毁时由 `EnemyController` 显式销毁自己的容器，在飞的子弹一起消失。
- 碰撞面按伤害源现算（`Bullet.ApplyHitMask`，`Bind` 时写一次）：
  玩家子弹排 `Default(0) | Player(7)`，只留敌人身体；敌人子弹排 `Default(0) | Ground(6) | Enemy(8)`，只留玩家身体。
  两侧都必须排 `Default`：玩家的近战盒与弹反盒都在 0 层，放进来子弹会被它们提前收走，弹反也就扫不到飞进来的敌弹。
  预制体上的那份 `ExcludeLayers` 因此只是开局默认值，运行时一律被覆盖。
- 于是敌弹伤玩家也走物理回调：子弹的 `AttackBox` 撞到玩家 `HurtCollider`（7 层）就交给 `PlayerLogic` 结算，
  不再需要每帧扫活弹表。`Bullet.OnTriggerEnter2D` 里「撞到目标层就放行、交给 `AttackBox`」同样按伤害源判（`HitLayer`）。

- 子弹伤害走它自己身上的 `AttackBox`：`Bind` 里 `SetAttack(this)` 把开火者交上去，击退方向取飞行方向。
- 同一次 `Bind` 还会 `SetOwnerRoot(开火者)`：子弹容器是独立根对象，`AttackBox` 的「同根」自伤判定对它不成立，
  而出膛点（控制器上的 `bulletMuzzle`）落在身体里或身体边缘时，那一帧的触发盒会压着发射者自己的受击盒，
  于是「白发子弹」会一发一发打在自己身上、三发之后整只消失。`SetOwnerRoot` 之后凡属于开火者层级的受击盒一律跳过。
- 玩家子弹命中受击盒：`AttackBox` 结算成功（血量真的掉了）、或命中把伤害值抹成 0 的站桩靶子
  → 回调 `IHitLanded` → `Bullet` 立刻把这一发还进池。一发只对一个目标结算一次，
  同帧里剩下的受击盒回调被「已结算」标记与摘掉的攻击者挡掉。撞到敌人层时**不自己收池**，交给 `AttackBox`：
  池化后 `SetActive(false)` 会当场掐断碰撞，先收就会把这一枪吞掉。
- 敌弹例外：`Bullet.OnTriggerEnter2D` 撞到受击盒就**自己结算并收弹**，不看 `TakeDamage` 的返回值。
  玩家在无敌窗里、那一发一点血都没扣，也照样消失——否则它会贴着人继续飞，窗口一过又结算一次。
- 站桩靶子只把伤害值抹成 0：血量不减、不开无敌窗，但受伤态、击退、极性值与子弹消失都照常，打上去的手感和活敌人一致。
- 黑形态的近战走同一套 `AttackBox`，三只判定盒（`Player/BlackDash/AheadCollider | UpCollider | DownCollider`）
  平时是关着的：普攻点亮 `AheadCollider`（`BlackAttackView.BeginFlat`），突进点亮 `Up` / `Down` 中对应的那一只
  （`BeginDash`），各自由 `End` 关掉。
  因此**不需要** `IIntervalAttacker`：盒一关一开就是一次挥击，`OnTriggerEnter2D` 每只目标各收到一次，
  同帧两个敌人都在判定里也都能吃到；开 `OnTriggerStay2D` 反而会因为间隔把所有目标一起挡住。
- 近战的 `DamageSource` 是 `Melee`：`PlayerLogic` 只拦 `PlayerBullet`，`EnemyLogic` 只拦 `Contact` 与 `EnemyBullet`，
  Melee 两边都不误伤。命中同样走 `IHitLanded`，所以普攻与突进也算"有效攻击"，一样涨极性值、一样顿帧（`meleeHitStopTime`）。
- 普攻的判定盒**摘父级、冻在开打那一刻的位置**；突进盒**不摘父级**，整段跟着玩家跑。
  突进只吃斜上 / 斜下（站在地面时斜下连起手都不成立，空中三个方向都能起），撞上谁就按 `blackDashDamage` 扣血、
  沿突进方向击退（`blackDashKnockback`）。
- 一次突进对**同一个受击盒只结算一次**：三只突进盒共用一份 `HitLedger`，`BeginDash` 时清空，
  第一次接触就把该 `HurtBox` 记下，之后换盒、离开再进都不再扣；换一只怪照常各吃一次。
  命中第一个目标就**提前结束突进**：`ProduceDamage` 走 `SetHitHandler` → `BlackDashState.NotifyHit`，
  下一帧退出本体，`Exit` 把 y 换成 `blackDashBounceSpeed` 弹起、x 保留，重力同时恢复。
  撞墙（`WorldInfo.TouchingWall`）同样提前结束，但 `Exit` 把速度清 0。两种都进后摇。
- 普攻与突进用的是**同一套账本**，但每次开打都会清空（`BeginFlat` / `BeginDash` 各清一次）：
  所以「普攻一次只打同一目标一次」，而「普攻→突进」「上突进→下突进」之间同一个目标可以再吃一次。
- 范围展示：紫色是突进盒真实形状（随盒移动，实时位置）；绿色是起手形状沿突进位移扫过的凸包
  （`BlackAttackView.PaintSweep`，世界坐标固定，`End` 时销毁），用来核对「判定到底扫了多宽多长」。
- 普攻的后坐力分空挥/命中两份：开打时先按空挥那份推（`flatAttackMissRecoil`），
  判定盒一碰到受击盒就把空挥那份换成命中那份（`flatAttackHitRecoil`）。
  触发点是 `AttackBox` 取伤害那一刻（`ProduceDamage`），**不看扣血结果**：无敌窗、关掉 AI 的站桩靶子照样有反冲。
  一次挥击只换一次，同帧砍到多个敌人也只换一下，`Exit` 之后迟到的命中不再换。
- 反冲方向沿朝向反向推（只有横向），给敌人的击退不受这条影响。
- 反冲落地方式：直接写速度（`SetVelocityX`），不走外部速度——反冲是瞬时的，
  写完当帧就交给移动组接管，没有外部速度那层逐帧衰减的拖尾。
- 命中那份要晚一帧才写：接触回调在物理步里、晚于 `Commit`，当场写会被下个 `BeginStep` 冲掉，
  所以 `NotifyHit` 只排队，下一帧 `Tick` 才 `Apply`（`Exit` 也补一次）。
- 受击（`ConditionGroup.IsHurt`）期间攻击键不生效，不会起手；已经起手的一套不打断。
- 普攻点亮判定盒后盒子**脱开玩家、冻在开打那一刻的世界位置**：`BlackAttackView.BeginFlat` 里 `SetParent(null, true)`，
  玩家之后再跑、再转身都不拖着判定走，`End` 才关掉并装回 `BlackDash` 下，下一次攻击按新站位重新初始化。
  盒摘走后层级里认本体靠 `AttackBox` 缓存的前根（`_selfRoot`），否则会打到玩家自己。
- 判定盒点亮时，盒下会挂一片半透明紫色网格，就是该 collider 的真实形状（`Collider2D.CreateMesh` + `MeshRenderer`，
  `BlackAttackView.Paint`）：网格顶点在盒的局部空间，形状与判定完全一致；它是盒的子物体，盒一关跟着消失。
- **三只判定盒必须留在 Default 层（0）**，不能放回玩家层（7）：
  敌人的身体受击盒在 `ExcludeLayers` 里排掉了 7|8（免得被玩家和同类推开），
  被排除的一对碰撞体根本不会产生接触，盒子挂回玩家层就是"看着在挥，一点伤害都没有"。
  子弹一直是 Default 层，所以白攻击不受这条影响，这也是当初只有近战打不到的原因。
- 这条排除的直接结果是**玩家和敌人能重叠**：两侧身体互不产生接触，可以直接穿到对方中心，既不阻挡也不互相推挤。
  贴脸时的接触伤害、近战判定全靠触发器（`AttackCollider` / 判定盒）结算，**不要指望身体碰撞把两者分开**；
  需要分离感就得自己加推力，或者改成双方不排除、只让同类互推。
- 敌人的 `AttackCollider` 半径只要能盖到玩家受击盒就够：身体不挡人，玩家可以贴到中心距 0，
  0.9 的圈在水平 0.9 + 0.45 = 1.35 以内都能命中；真正打不到的情形只有站在高低差上、中心距超出这个范围。
- 敌人之间会互相挤压，所以 `EnemyController` 丢弃 `DamageSource.Contact` 与 `EnemyBullet` —— 接触伤害与敌弹只对玩家生效。
- 子弹打在 `Ground` 层、离开 `Bound` 触发器，或命中敌人结算完，都回 `Pool<Bullet>`，不是 `Destroy`。
- `Bound` 是**整张可行走地图的边界多边形**，所以子弹一出生就压在它里面：
  - `OnTriggerEnter2D` 里必须**放行** `Bound`（按 tag 判断），否则第一次物理步就把刚出膛的子弹收回池，表现为「打不出子弹」。
  - 只有在 `OnTriggerExit2D` 里才收 —— 也就是子弹真的飞出了地图。
  - 传输（残影路径）期间会禁用碰撞体，**禁用也会发退出回调**（`Physics2DSettings ▸ Callbacks On Disable`），
    所以退出回调里先判 `_state == Flying`，否则子弹一进残影就被自己销毁。
- `ExcludeLayers` 由 `Bullet.ApplyHitMask` 在 `Bind` 时按伤害源写；预制体上那份 `183` 只对还没 Bind 的实例有意义。
  `Bound` 只在 `Level_1` 被设到 `Bound`(10) 层，`Level_2~5` 还留在 `Default`(0)：
  那几关的子弹收不到离开回调，飞出地图也不会回池（玩家子弹排掉 Default 后连碰都碰不到它）。
  把 5 个关卡的 `Bound` 统一到 `Bound` 层后才算干净。

- 弹反范围在 `Player/BlackRebound/{Ahead,Up,Down}Collider`，跟着近战本体一起开关（只开选中那一路：普攻开 Ahead、突进开 Up 或 Down），
  但**不脱开玩家**：留在层级里，靠根节点翻 `localScale.x` 跟随转身；判定盒那套"摘下来冻住"不适用于它。
- 弹反不走触发器：弹反盒在 Default 层，而两侧子弹的命中面都排掉了 Default，物理根本不会回调。
  `BlackAttackView.ReboundTick`（`PlayerController.FixedTick` 里调）每物理帧拿盒子的真实形状
  （`Collider2D.OverlapPoint`）扫一遍活子弹表（`Bullet.LiveCount` / `LiveAt`），"飞进来"与"开打时已经在里面"是同一套判定。
- 只有 `Bullet.PlayerOwned == false` 的敌弹会被弹：`Bullet.TryReflect` 把玩家自己的 `IBulletLauncher` 叫到
  原位置反向重发一发（速度沿用原弹，伤害 / 击退 / 传输速度取 `bulletDamage` / `bulletKnockback` /
  `bulletTransferSpeed`），原弹当帧从敌方系统收走。新弹归玩家侧，打敌人、走残影、涨极性值都照常。
- 优先级：子弹中心落在身体受击盒包围盒里就不弹（`BlackAttackView.InHurtRange`），留给物理回调的那次受击结算。
  两边按设计不重叠，这条只在同一颗子弹同一帧同时压进两边时生效。

## 六、生命与死亡

- 血量由 `ActorLogic` 持有（`CurHealth` / `MaxHealth` / `IsAlive` / `ResetHealth`），条件组只管无敌窗与击退；
  `CharacterConfig.maxHealth`（点）与 `invulnerableTime`（秒）是通用项，玩家和敌人各有一份。
- 时间一律取 `LogicContext.GameTime.now`（固定帧时间），表现层的物理回调里调用 `TakeDamage` 时，
  用的是上一个固定帧记下的 `now`，误差不超过一帧。
- 敌人血量归零：`EnemyController` 在当帧固定帧末尾 `Destroy` 自己（没有死亡演出）。
- 玩家血量归零：暂时**回满血 + 退回最近落脚点**（与掉出世界同一套兜底），没有独立死亡流程。
- 折跃（世界反转成功）也会 `ResetHealth()` 回满血，但不清无敌窗与受伤态。
- 无敌窗有两个来源，分开计时：受击后的 `CharacterConfig.invulnerableTime`，与充能冲刺落影时给的
  `PlayerConfig.dashInvulnerableTime`。`ActorLogic.TakeDamage` 命中任一窗口就整次不结算 —— 不扣血、不进受伤态、不吃击退。
  表现层也按来源分开：冲刺无敌把 View 固定在写死的透明度（100/255），受击无敌窗才是闪烁。

## 七、极性值（玩家）

- `PlayerConfig.maxPolarity`（点）与 `polarityPerHit`（点）：每次**有效攻击**加一份，涨到上限截断，不会为负。
- 折跃连线造成的伤害也算有效攻击，但增量是单独一项 `afterimageLinkPolarity`（点）：
  `AfterimageField` 每打中一个目标就发一次 `AfterimageLinkHit`，`PlayerLogic` 订阅后按这一项加值。
  一段线可能压着多个目标，也可以是同一颗子弹连续穿多段，各算各的。
- 有效攻击的判据是 `IHurtable.TakeDamage` 的返回值 —— 血量真的掉了才算。
- 唯一的例外是站桩靶子：`EnemyController` 关掉 OpenAI 后，`EnemyLogic.TakeDamage` 把伤害值抹成 0 交给基类
  （受击态、击退、无敌窗都照走），但**返回值不再按「血量掉了没有」算**，改成「活着且不在无敌窗」就返回 true。
  `AttackBox` 因此照常走 `MarkHit` 与 `IHitLanded`，受击态、击退、极性值、子弹命中回池都和活敌人一致，只差血量不变。
- 受击无敌窗内、目标已死仍然不涨：`EnemyLogic.TakeDamage` 在这两种情况下返回 false，`AttackBox` 直接返回。
- 近战也走这条链路（`BlackAttackView` 实现 `IHitLanded`，转给同一个 `PlayerController.HitSink`）。
- 回报链路：`AttackBox` 结算后确认这一下算命中（扣了血，或目标是返回 true 的站桩靶子）→ 攻击者实现了 `IHitLanded` 才回调 →
  `Bullet` 把它转给生成时传入的接收者（`PlayerLogic.OnHitLanded`）。
  敌人的接触伤害不实现该接口，所以敌人的 `AttackBox` 不会误触发。
- 极性值存在 `PlayerLogic` 里：换场景重建即归零；`Revive()`（死亡回档）也会清空。
- 调试面板显示 `极性：当前/上限`。

## 八、已知限制

- 敌人受击不中断三段攻击：门禁会压住冲刺速度，但状态计时照走，受伤结束后可能直接跳到后摇。
- 击退期间不施加重力以外的竖直修正；斜坡上被击退可能短暂离地。
- 没有受击硬直/闪白等表现，`Damage.Point` 目前只用于将来做受击方向演出。
