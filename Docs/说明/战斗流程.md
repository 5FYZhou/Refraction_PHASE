# 战斗与受击流程

> 依据代码：`Logic/Combat`（契约）、`Logic/Actor/ActorLogic`（血量）、
> `Logic/Actor/ConditionGroup`（受击无敌与击退）、
> `Presentation/Actor/AttackBox`、`HurtBox`、`Presentation/Combat/Bullet/Bullet`。

## 一、契约

| 类型 | 位置 | 语义 |
|---|---|---|
| `IAttacker` | Logic.Combat | `ProduceDamage()` 给出一份伤害快照，不带目标 |
| `IHurtable` | Logic.Combat | `bool TakeDamage(in Damage)`，实现方是 `ActorLogic`（玩家与敌人共用）；返回值 = 血量是否真的减少 |
| `IHitLanded` | Logic.Combat | `OnHitLanded()`，伤害落地后的回报；只有真心扣血的攻击者才实现 |
| `IAlivable` | Logic.Combat | `IsAlive`，血量为 0 后为 false |
| `Damage` | Logic.Combat | `Direction`（指向受害者）/ `Amount`（点）/ `KnockbackSpeed`（单位/秒）/ `Source` |

## 二、一次伤害的路径

1. 表现层发现重叠：`AttackBox.OnTriggerEnter2D`（伤害结算）与 `Bullet.OnTriggerEnter2D`（残影与 Bound 分流）。
2. 定位受击实现：`HurtBox.Resolve(other)` —— 先找碰撞体上的 `HurtBox`，再往父级找，最后退回根上的 `IAttackable`。
   **碰撞体常常只是身体件**，`HurtBox` 却挂在另一个子节点上，只查本层会整台角色判不到。
3. `IAttackable.TakeDamage` → `ActorLogic.TakeDamage`（血量在这一层扣）→ `ConditionGroup.RegisterHit`：
   - 无敌窗内整下吞掉（返回 false，血量与击退都不变）。
   - 有伤害值就扣点；扣了血才开无敌窗（0 伤害的纯效果不占用窗口）。
   - 有击退就排队，等下一个固定帧起步。
4. 下一个固定帧 `ConditionGroup.Tick` 把击退交给 `HurtState`，并切到 `Hurt`。

## 三、固定帧序（`ActorLogic.FixedTick`）

```text
BeginStep → ConditionGroup.Tick → 子类逻辑 → ApplyGravity → Commit → ApplyGates
```

- `ConditionGroup.Tick` 先跑：它决定本帧是否受伤，并**创建** `MoveGates`。
- `ApplyGates` 必须压在 `Commit` 之后：门禁写的是绝对速度，早一步就会被本帧状态与重力盖回去。
- 因此受伤期间，任何状态写出的速度都被丢弃 —— 这是"击退期间不可控"的唯一实现点，不要在各状态里各自判断 IsHurt。

## 四、击退

- 初速度由 `Damage.KnockbackSpeed`（单位/秒）直接给出，受击者不再折算格数。
- 减速：`HurtState` 每帧减去 `KnockbackDecay × Δt`，减到 0 就退出受伤态；
  滑行位移 = `v0² / (2 × KnockbackDecay)`，想调远近就改伤害里的初速度或目标自己的阻尼。
- 纯横向击退不接管竖直速度（沿用帧首的 vy），否则空中挨打会当场停在半空。

## 五、各角色的伤害来源

| 来源 | 触发 | 数值 |
|---|---|---|
| 玩家的白子弹 | `Bullet` 上的 `AttackBox` 命中受击盒 | `bulletDamage` / `bulletKnockback`（`PlayerConfig`） |
| 敌人的接触伤害 | `AttackBox` 碰到玩家 | `contactDamage` / `contactKnockback`（`EnemyConfig`） |

- 子弹伤害走它自己身上的 `AttackBox`：`Bind` 里 `SetAttack(this)` 把开火者交上去，击退方向取飞行方向。
- 结算成功（血量真的掉了）→ `AttackBox` 回调 `IHitLanded` → `Bullet` 立刻把这一发还进池：
  一发只对一个敌人结算一次，同帧里剩下的受击盒回调被「已结算」标记与摘掉的攻击者挡掉。
- 子弹撞到敌人层时**不自己收池**，交给 `AttackBox` 结算：池化后 `SetActive(false)` 会当场掐断碰撞，
  先收就会把这一枪吞掉。
- 2D 里**触发器不会和触发器产生回调**：敌人的 `AttackCollider` 是触发器，玩家的 `HurtCollider` 也是触发器，
  真正触发的是玩家那件**非触发器的身体碰撞体**，所以 `HurtBox.Resolve` 的逐级回退是必需的。
- 敌人的 `AttackCollider` 半径必须**大于身体碰撞体**（身体 r=1，攻击圈 1.25）：贴在圈里就永远碰不到玩家，
  接触伤害等于没接。
- 敌人之间会互相挤压，所以 `EnemyController` 丢弃 `DamageSource.Contact` —— 接触伤害只对玩家生效。
- 子弹打在 `Ground` 层、离开 `Bound` 触发器，或命中敌人结算完，都回 `Pool<Bullet>`，不是 `Destroy`。
- `Bound` 是**整张可行走地图的边界多边形**，所以子弹一出生就压在它里面：
  - `OnTriggerEnter2D` 里必须**放行** `Bound`（按 tag 判断），否则第一次物理步就把刚出膛的子弹收回池，表现为「打不出子弹」。
  - 只有在 `OnTriggerExit2D` 里才收 —— 也就是子弹真的飞出了地图。
  - 传输（残影路径）期间会禁用碰撞体，**禁用也会发退出回调**（`Physics2DSettings ▸ Callbacks On Disable`），
    所以退出回调里先判 `_state == Flying`，否则子弹一进残影就被自己销毁。
- **碰撞体层级现状（有隐患）**：`Bullet.prefab` 的 `ExcludeLayers` 是 `183`，排掉
  Default / TransparentFX / IgnoreRaycast / Water / UI / Player，放行 Ground(6)、Enemy(8)、Bound(10)。
  代码不再在 `Bind` 里改写排除表，层过滤只靠这份预制体设置。
  `Bound` 只在 `Level_1` 被设到 `Bound`(10) 层，`Level_2~5` 还留在 `Default`(0)：
  那几关的子弹收不到离开回调，飞出地图也不会回池。把 5 个关卡的 `Bound` 统一到 `Bound` 层后才算干净。

## 六、生命与死亡

- 血量由 `ActorLogic` 持有（`CurHealth` / `MaxHealth` / `IsAlive` / `ResetHealth`），条件组只管无敌窗与击退；
  `CharacterConfig.maxHealth`（点）与 `invulnerableTime`（秒）是通用项，玩家和敌人各有一份。
- 时间一律取 `LogicContext.GameTime.now`（固定帧时间），表现层的物理回调里调用 `TakeDamage` 时，
  用的是上一个固定帧记下的 `now`，误差不超过一帧。
- 敌人血量归零：`EnemyController` 在当帧固定帧末尾 `Destroy` 自己（没有死亡演出）。
- 玩家血量归零：暂时**回满血 + 退回最近落脚点**（与掉出世界同一套兜底），没有独立死亡流程。
- 折跃（世界反转成功）也会 `ResetHealth()` 回满血，但不清无敌窗与受伤态。

## 七、极性值（玩家）

- `PlayerConfig.maxPolarity`（点）与 `polarityPerHit`（点）：每次**有效攻击**加一份，涨到上限截断，不会为负。
- 有效攻击的判据就是 `IHurtable.TakeDamage` 的返回值 —— 血量真的掉了才算：
  受击无敌窗内、目标已死、伤害值为 0（例如关掉 AI 的站桩靶子）都不涨。
- 回报链路：`AttackBox` 结算完发现血量下降 → 攻击者实现了 `IHitLanded` 才回调 →
  `Bullet` 把它转给生成时传入的接收者（`PlayerLogic.OnHitLanded`）。
  敌人的接触伤害不实现该接口，所以敌人的 `AttackBox` 不会误触发。
- 极性值存在 `PlayerLogic` 里：换场景重建即归零；`Revive()`（死亡回档）也会清空。
- 调试面板显示 `极性：当前/上限`。

## 八、已知限制

- 敌人受击不中断三段攻击：门禁会压住冲刺速度，但状态计时照走，受伤结束后可能直接跳到后摇。
- 击退期间不施加重力以外的竖直修正；斜坡上被击退可能短暂离地。
- 没有受击硬直/闪白等表现，`Damage.Point` 目前只用于将来做受击方向演出。
