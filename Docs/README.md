# Docs 文档地图

> 本目录按「面向谁 / 讲什么」分目录。**移动文档时请同步本文件与各文件的相对链接。**
> 文档是**快照，不是契约**：`.md` 与代码冲突时以代码为准，回头把 `.md` 改回来；
> `Docs/**/*.txt` 是用户手写的需求，**只读**（见 `AGENTS.md` §3）。

| 目录 / 文件 | 给谁看 | 装什么 |

## 程策交接撰写规则

**用途**：只回答一个问题——**这次改动给策划多了什么、去哪儿找**。
策划侧**只读，不需要写、不需要维护**。

### 边界

- **只记增量，从 2026-11-24 起**。这天之前就存在的可调项（`PlayerConfig` 那些数值、各敌人 config、
  存档点、视差背景……）策划已经知道，**不追述、不补登记**；以后改了才写。
- **SO 只写「新增了哪一份、在哪」**，字段含义与取值看 Inspector 里的 Tooltip，**不在文档里复述**。
- **一项一句，≤ 30 字**（路径、名称不计）。说明写不下就是写多了，砍掉。

### 文件

- 一天一个文件，命名 `YYYY-MM-DD.md`（本地日期），放 `Docs/程策交接/`，不建子目录。
- 当天没有可调项变更就**不建文件**。
- 只**追加当天文件**；历史文件只在写错时订正。跨天的改动记在交付那天，不重复记。

### 结构

大标题 = **对象**，一行一个 `##`，同一对象在一个文件里只出现一次：

```text
## 玩家
## 玩家-黑攻击范围可视化
## 敌人-Warrior
## 场景-存档点
## 场景-视差背景
```

小标题**只写有内容的**，顺序固定为 `### 新增` / `### 修改` / `### 删除`；
某一类今天没有就不写，**不写「无」占位**。

### 每一条怎么写

```text
- 黑攻击 / 弹反 / 扫掠范围的显示开关与颜色 — `Assets/Resources/Data/BlackAttackVisualConfig.asset`
- 站立 / 下蹲开火点（Muzzle Stand / Muzzle Crouch） — `Assets/Resources/Prefabs/Player.prefab` ▸ 根节点 ▸ PlayerController
```

硬要求：

1. **名称在前，路径在后**，中间用 `—`。名称用策划在 Inspector 里看到的那一套（`Muzzle Stand`），
   需要时括号补代码字段名（`muzzleStand`）。
2. **路径必须真实可点**：资产写完整文件路径（从 `Assets/` 起），Inspector 字段写到
   `预制体路径 ▸ 节点 ▸ 组件`，层级用 `▸`。不写「在 Player 上」。
3. **默认不写说明**。只有在「不写就会理解错」时才补一句 ≤ 30 字的括号：
   数值的含义、局部坐标要填正数、改了要重进游戏、资产还没建。
4. **不写**：字段列表、单位与量纲、Tooltip 原文、默认值、调参建议、变更史、TODO、调用链。
5. **`.txt` 需求文档永远不动**：交接写「现在能调什么」，需求写「想要什么」。

### 谁维护、什么时候写

- **AI 负责维护**：改动涉及 SO 新增/改名/删字段、预制体新增可调字段、`Resources/` 下资产改名或挪位、
  新增可视化开关，就当天补一条；文件不存在就新建（标题 + 只含有内容的小标题），一条也算。
- **漏记 = 交付不完整**，和门禁失败同级；`AGENTS.md` §8 DoD 有这一条。
- 策划改了数值不用回写；发现某条路径点不进去，说明条目过期，找程序改。
